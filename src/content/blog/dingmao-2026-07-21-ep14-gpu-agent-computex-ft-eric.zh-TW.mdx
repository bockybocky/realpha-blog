## 這集在講什麼

《定錨產業筆記》這一集，是主持人與研究經理 Eric 聊 Computex 2026 的現場觀察。他們跑了兩個場館：南港展覽館這邊是台廠、電源方案與零組件的主場；TICC 那邊是輝達自己辦的場，展的是新一代機櫃架構與地端應用。錄音時間是七月十六日下午，剛好也是台積電法說會那天。

**原集**：定錨產業筆記 EP14〈從 GPU 算力到 Agent 執行：Computex 揭露的伺服器分工革命 ft. Eric〉（2026-07-21 上架，各大平台搜「定錨產業筆記」）

我一開始是當展場流水帳在聽的。真正讓我停下來的，是中間一句很小的事實：某顆伺服器 CPU 原本搭配的記憶體模組，容量被砍成一半。那不是新聞，那是一個有代價的動作——而有代價的動作，比任何一張路線圖都誠實。以下是我聽完之後自己的整理與延伸，不是節目內容的重述。

## 摘要重點

**Agent 化最直接的後果，是 CPU 從配角被推上前台。** 過去資料中心裡 CPU 與 GPU 的數量比大約是一比八、一比四；節目引用的說法是，這個比例正往一比二靠，某些應用甚至會走到兩者差不多、或者 CPU 更多。原因不難理解：模型不再是問一句答一句，而是自己規劃、自己分派、自己一步一步執行，那些「決定接下來要做什麼」的工作大量落在 CPU 上。展場上最能說明這件事的畫面，是輝達展出的 CPU 機櫃——整櫃塞進 256 顆 CPU，而同世代的 GPU 機櫃一櫃也就幾十顆晶片。連帶的兩個外溢效應也被點到了：CPU 廠把產能鎖給更貴的伺服器型號，消費性那端的供給被排擠；而每一顆 CPU 都要配記憶體，DDR5 與伺服器用模組的需求跟著被墊高。

**一次把記憶體模組砍半，是這集最誠實的一段。** 那顆 CPU 原本規劃搭 192GB 的模組，實際看到的是降到約 96GB。理由是兩件事撞在一起：記憶體供應本來就不夠，而 CPU 用量又在暴增。公司做的選擇是——寧可規格難看，也要準時出得了貨。這句話把優先順序講得很白：在缺料的時候，交期比帳面規格值錢。

**管理層自己長出了階層。** 節點一多，麻煩的不是算得快不快，是「誰來管這一堆節點」。伺服器管理晶片（BMC）過去一顆管一台，新一代已經有版本可以一顆管兩個節點；再往上，供應商推的是一種衛星式的階層管理——一顆主要的 BMC，底下掛一堆小的管理晶片分散在各處，遠端監控、省成本。同一條線上還有一顆新品，把可程式邏輯晶片（FPGA）直接整合進小管理晶片裡。理由很實際：以前這兩顆要分開擺，整合之後不只效率好，還省下板子上那點極珍貴的空間。**板上空間也是一種會缺的資源**，這件事平常沒人談。

**最前緣的東西，同時在延後。** 兩件事被放在一起講：一是刀鋒式機櫃架構，因為背板互聯、機構設計與材料驗證的不確定性太多，蠻有機會延到下一個世代才導入；二是下一代旗艦 GPU 原本規劃一個封裝裡放四顆運算晶粒、封裝面積上看光罩的九倍，但受限於封裝的翹曲等難題，市場開始認為它可能維持兩顆，那樣一來整代的升級就只剩記憶體從 HBM4 走到 HBM4e。這兩件事指向同一句話：**這一代真正的天花板，不在設計，在能不能做得出來、驗得過。**

**800V 那面牆前面，大家把臉貼上去看。** 南港二館一樓有一整面電源與零件的展示牆，主題就是 800V。各家展的是轉換階梯——800V 轉 50V、800V 轉 12V——伴隨的是板上一整排電容：大顆的直立式電容一塊板上五六顆、十幾顆都有，也有搭配高分子混合型的。Eric 提到一個很有畫面的細節：800V 的電源線，粗細跟一個成年人的小手臂差不多，而且很重。但這裡有個容易誤讀的地方——**這波缺的是高壓高容那種特定規格，不是整個電容產業都缺**；而真正在大量出貨的仍然是低壓那一段。

**有些東西只有現場才給得了。** Eric 那天本來在南港開會，散場已經快十一點，猶豫要不要衝去北流聽主題演講——想想人都到了，還是去了，只排到最上層看台。開場影片放完輝達一路走來的歷程，最後停在未來台北總部的畫面，打上一句「台北，一切的起點」。他說當下眼眶就熱了，然後補了一句很有意思的話：在這個產業裡工作的人可能也在流淚，因為這一切都是供應鏈的人每日每夜做出來的。這種現場感不只是情緒——你只有站在機櫃前面，才數得出一塊板子上到底有幾顆電容、電源線到底有多粗。

## 延伸想法

**一、降規與延後，是免費的瓶頸偵測器。**

我這幾年越來越信一條土辦法：**只看有代價的動作，不看沒代價的宣示。** 路線圖、市場規模預估、展會上的願景，這些講錯了不用付錢；但把記憶體模組從 192GB 砍到 96GB，是拿產品競爭力去換交期，這是要付錢的。同一類的還有預付款、產能重排、把整代架構延後。

這集剛好給了兩種讀法。**降規告訴你「缺什麼」**——公司願意犧牲的那一項，就是它拿不到的那一項。**延後告訴你「卡在哪一層」**——刀鋒架構卡在背板與機構驗證，旗艦封裝卡在翹曲，兩個都不是設計問題，是製造與驗證問題。這比「哪一層是瓶頸」的口頭推論可靠，因為它已經反映在別人的行為上了。

但我要把失效條件也寫出來，不然這條就變成萬用解釋。**降規至少有兩種完全不同的成因：一種是上游缺料，一種是下游需求縮了。** 兩者長得一樣，讀反了會虧錢。可以拿來分辨的線索是：如果是缺料，同一時間該零件的價格會往上、交期會拉長，而且其他吃同一種料的產品也會出現類似的取捨；如果是需求縮了，你會看到反過來的組合——降規伴隨的是價格鬆動、交期縮短。這集判斷是前者，因為記憶體那端同時在缺，而 CPU 用量在增加。**這個判準的好處是它可以被推翻**：只要下一季看到那類模組的報價往下、交期變短，這段推理就得整段作廢。

**二、剛需不等於定價權，這是瓶頸換層之後最容易踩的坑。**

多節點架構確實把一批原本沒人談的東西變成「非它不可」：管理晶片、電源轉換、被動元件、伺服器 CPU。但「非它不可」跟「賺得到錢」是兩件事。我會用三個問題過一遍：**這一層有幾家做得出來？客戶換掉它的成本多高？量增有沒有伴隨價增？**

第三個問題最常被跳過。電容顆數從五六顆變十幾顆，那是量；如果規格是通用的、誰都能做，量增會被單價下滑吃掉，最後營收只多一點點，毛利還可能更差。反過來說，這集裡有一個訊號是往定價權方向走的：**當板子上的空間變成稀缺資源，整合者會吃掉鄰居。** 把可程式邏輯晶片併進管理晶片這件事，對整合的一方是提高單價與黏著度，對被整合掉的那一方卻是「需求還在，但位置沒了」——那顆料的市場沒有變小，只是不再需要單獨買一顆。這是一個機會與風險同體的訊號，不能只讀一半。

還有一層是組合風險。這集裡的 CPU、管理晶片、電容、電源方案，看起來分散在四個不同的產業，但它們**共用同一個假設**：多節點架構如期放量。如果那個假設出問題（例如整代架構延後，這集自己就講了刀鋒可能延），四個部位會一起錯。**同一個瓶頸敘事同時解釋你手上好幾個部位時，那不是分散，那是同一個賭注被拆成四張單。**

**三、同一件事，正在兩個尺度上發生。**

節目裡有一段我覺得被低估了。Eric 談他在展場看到的地端應用時，順口講了自己對下一階段的想像：先用地端的小模型做工作分類與流程拆解，拆完再依任務性質決定要叫哪一個模型來做，藉此省掉大量不必要的算力花費。

這跟整集在講的機櫃架構，其實是同一件事的兩個尺度。**機櫃裡：一堆節點需要一套管理層來調度；模型這邊：一堆模型也需要一個調度者決定誰來做。** 兩邊的價值都從「誰算得最快」移到「誰決定由誰來算」。老子那段話講得比我清楚——三十根輻條共用一個轂，真正讓車能轉的，是轂中間那個空的地方；有形的部件提供便利，無形的空缺才成就用處。晶片是「有」，調度層是「無」。

不過我得誠實標一句：**這一段是節目裡最沒有硬證據的部分**，它是一位研究員的個人推測，不是展場上量得到的東西。所以我的處理方式是把它寫成一個要對答案的問題，而不是一個結論。這集我最後留下的三個追蹤題，都是同一種寫法：刀鋒式機櫃到底有沒有如期導入？下一代旗艦封裝最後是兩顆晶粒還是四顆？CPU 與 GPU 的數量比，下一輪法說會上會被講成多少？

**結論會過期，問題不會。** 一場展會給你的，本來就不該是答案，是一批可以拿去對答案的題目。
