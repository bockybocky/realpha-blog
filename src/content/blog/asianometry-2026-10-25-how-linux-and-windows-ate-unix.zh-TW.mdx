2026 年 10 月 25 日 Asianometry 這集〈How Linux (and Windows) Ate UNIX〉，講的是企業伺服器市場在十幾年裡換了主人。1997 年，一盒 Red Hat 零售約 50 美元，一套 Windows NT 授權從 150 美元到 1,100 美元，而一台軟硬體配好的 UNIX 系統要 2.5 萬到 25 萬美元；到了 2002 年，Gartner 的數字是 Linux 伺服器硬體營收成長 63%、UNIX 硬體營收下滑 11%。這個替換先發生在低階與中階，高階資料庫靠 32 位元 x86 的記憶體上限又擋了好幾年，要等 2003 年 AMD 的 Opteron 把 64 位元帶進 x86 才鬆開。

![三條長度極度懸殊的橫條，最上面代表零售 Linux 的一小段，中間是 Windows NT 授權，最下面是長到幾乎跨滿整張圖的 UNIX 整機，顯示價格差的是數量級而非百分比](/figures/unix-linux-price-gap-1997.svg)

## 1990 年代初：一座座賣二十五萬美元的城邦

那時候要跑一台撐得住企業的伺服器，答案是 RISC 硬體加 UNIX 軟體。RISC 是一種把指令集做精簡、好做快的處理器設計；伺服器則是放在機房裡、透過網路把運算和資料餵給一堆使用者電腦的機器。

市場由垂直整合的系統廠商佔著：Sun Microsystems 賣自家 SPARC 晶片配 Solaris，IBM 是 POWER 配 AIX，惠普是 PA-RISC 配 HP-UX，還有 Silicon Graphics。一整套封閉、專有，價格到數十萬美元，而且買進去就走不掉——軟體綁著硬體，硬體綁著那家廠商的服務。

![四座各自獨立的高柱，每柱由作業系統、晶片、服務三塊疊成並被外框圍住，柱與柱之間的橫向箭頭被打叉，代表無法跨廠搬移](/figures/unix-vertical-city-states.svg)

Intel 那時剛在消費級 PC 贏完一輪。它靠的是一個會自己轉的圈：出貨量大，半導體良率就好；良率好，成本降、利潤升，現金再投回更好的製造。AMD 和 Cyrix 追不上這個圈。

![一個順時針循環的圓，五個節點依序是出貨量大、良率好、成本降、現金多、製造更強，圈外有兩個追不上的小方塊停在圓外](/figures/intel-volume-flywheel.svg)

Intel 認為同一套打法可以搬進伺服器。

## 1993 到 1996：Intel 的量，配上一套從頭寫的 Windows

要進伺服器，Intel 需要一個軟體夥伴，於是找上微軟與 Windows NT。NT 在 1993 年由 Dave Cutler 帶隊推出，骨子裡和消費版 Windows 是兩回事——消費版是在 MS-DOS 上面硬接一層圖形外殼，NT 則是為企業從頭寫的。

第一版跑在 386 上，能動，不驚人。NT 缺的功能比 IBM 的 OS/2、Novell 的 NetWare 和各家 UNIX 多，還要當年算豪華的 16MB 記憶體。1993 年賣了約 3 萬套，1994 年約 11.5 萬套。數字不好看，可是微軟就是會一直回來。

轉折在 1995 年底的 Pentium Pro：550 萬個電晶體、150 到 200MHz，對比第一代 Pentium 的 310 萬和 60MHz。它在某些整數測試上贏過當時最快的 RISC 晶片，這件事讓業界吃了一驚。MIPS R10000 很快追回來，但 Pentium Pro 已經把「桌機架構」的效能天花板重新畫過一次。

![兩組柱狀圖，電晶體數與時脈都從矮柱跳到接近兩倍與三倍高的柱，上方一條原本的 RISC 高線被新柱頂破](/figures/pentium-pro-ceiling-redrawn.svg)

同一年中，Intel 開始發一種叫「Standard High Volume Servers」的參考板，讓合作廠商照著做、縮短上市時間。第一代板子支援 1 到 4 顆 Pentium Pro、1 到 2GB 記憶體、幾百 GB 儲存，Intel 說可以吃每秒 2,000 筆交易。11 月的發表會上，產品線從 2,600 美元的工作站排到 2 萬美元的伺服器。搭上 NT 4.0，1996 年 NT 銷售成長 85%，IDC 給它 27% 市占。

不過 Intel 心裡清楚，把企業市場的未來鎖在微軟身上有風險。1995 年它推一套叫 NSP 的多媒體軟體標準，想把音訊影像的運算從周邊搬回 CPU，好讓大家買更快的處理器；微軟認定這是繞過作業系統的中介層，公開宣布不支持，比爾・蓋茲還寄了一封信給安迪・葛洛夫表達不爽。這件事後來在反托拉斯訴訟裡被當成例子翻出來，兩邊當場都說沒事，可是 Intel 記住了：這個夥伴願意動用它的槓桿，去殺掉它不喜歡的東西。

更麻煩的是 NT 從一開始就寫成可移植的，除了 x86，也跑在 DEC 的 Alpha、IBM 與蘋果的 PowerPC、MIPS 上。微軟一邊簽著更多晶片支援，一邊就站在 Intel 面前側翼包過去。如果 NT 拿下市場，Intel 會不會被降級成「眾多硬體架構裡的一種」？

節奏也對不上。摩爾定律讓 Intel 兩年就有新晶片，微軟三到五年才出一版 Windows，而那一版不見得用上晶片的全部本事。最有名的例子是 Intel 1985 年就出了 32 位元的 386，微軟要到 1995 年的 Windows 95 才有 32 位元的消費版作業系統，中間隔了十年。

![上下兩條時間軸，上軸的晶片節點密集排列，下軸的作業系統節點稀疏，兩軸之間用一段長括號標出 32 位元從硬體到軟體相隔十年](/figures/silicon-vs-software-cadence.svg)

Bob Colwell 在《The Pentium Chronicles》裡還記了一段：微軟在多次會議上告訴 Intel，代號 Chicago 的 Windows 95 會是純 32 位元、拔掉 16 位元舊碼，Intel 因此放心把 Pentium Pro 往 32 位元效能最佳化；1994 年微軟公開宣布 Chicago 的圖形顯示介面會留在 16 位元。開發週期來不及改了，晶片上市後 Intel 被媒體嫌桌機繪圖效能差。

伺服器這邊，Intel 在意的是 NT 4.0 每個作業系統實例只支援 4 到 8 顆處理器，天花板擺在那裡，高階就進不去——有些 UNIX 能吃到 64 顆。這個落差回到兩家的成長模型：Intel 要靠賣新晶片長大，所以想要能幫它賣晶片的軟體；微軟要服務整個既有用戶基礎，所以慢、顧向下相容。開發一版 Windows 動用上千名員工、花掉幾十億美元，軟體就是這樣。

所以 Intel 想找替代方案。1990 年代後期，雷達上出現了一個很強的候選：Linux。

## 回頭補一條線：1984 年的 GNU 到 1995 年的 Red Hat

1984 年 1 月，MIT 的程式設計師 Richard Stallman 正式啟動一個要取代 UNIX 的計畫。他出身 MIT 的人工智慧實驗室，那裡原本靠 Lisp 做早期 AI 研究；等商人看出 Lisp 和它撐起的 AI 是門大生意，實驗室裂成兩家公司，Symbolics 募到幾百萬美元、把實驗室最強的駭客挖走，留下一個空殼。Stallman 沒有原諒這件事，他後來的說法是「Everything's dying」。

失去一個社群的感覺推著他去建一個新的，地基是自由軟體。他照著 UNIX 的設計原則——模組化、能跨硬體移植——重寫一套免費的作業系統，為了商業機密的理由不抄原始碼。這東西叫 GNU，他自己解釋成「GNU's Not UNIX」。他不知道做不做得完，可是不開始就永遠不會知道。

接下來幾年，工具鏈一塊一塊長出來，缺的是核心。核心是作業系統和硬體之間那一層，管記憶體、管每個程序分到多少 CPU 時間、管磁碟空間，它一延再延。

![左右兩格對比，左邊的堆疊在工具鏈與硬體之間空著一層虛線缺口，右邊同一個位置被填上一塊實心的核心](/figures/gnu-missing-kernel.svg)

核心最後是一個 21 歲的芬蘭大學生 Linus Torvalds 補上的。他被一套叫 MINIX 的教學用 UNIX 系統啟發，1991 年 8 月在 MINIX 的 Usenet 討論群貼文說自己在做一個免費的業餘作業系統，順便徵求功能建議。那篇文從 MINIX 生態拉來了貢獻者，後來自己獨立出去，叫 Linux。第一個能用的版本 1991 年 10 月出來。

Torvalds 的角色很快從寫程式的人變成審改別人貢獻、把它們併進程式碼庫的人。這種被形容成市集的做法，讓 Linux 出新程式碼的速度快過公司。1992 年的 0.12 版採用了 Stallman 的 GPL 授權：誰都可以讀和改，但改完要是散布出去，改的部分也得開源。

這張授權做了兩件事。它擋掉公司把程式碼拿走、加點鹽、再當閉源商品賣回來，因此 Linux 核心躲過了當年把 UNIX 切得零碎的分裂；它也讓公司放心投人，因為投下去的改良不會被誰鎖走——後來連 IBM 都派幾百名員工貢獻程式碼。Torvalds 後來說，改用 GPL 是他做過最好的一件事。

![中央一池開源程式碼，往右通向閉源商品的箭頭被一道閘門擋住並打叉，往下的箭頭繞成迴圈把公司投入的改良帶回池中](/figures/gpl-one-way-gate.svg)

GPL 還撐起了另一門生意。Linux 是核心，等於一具引擎，重要，可是車子其他部分還缺著；早期玩家自己組沒問題，要一般使用者開車前先造車就不行。於是有人開始做「發行版」，把 Linux 核心和 GNU 專案或其他自由軟體的工具包成一包，用起來方便些。節目裡的比喻是高中時代大家互相傳的混音帶。

![左邊只有一具引擎方塊，右邊一台車的輪廓把同一具引擎連同四塊周邊零件整台包進去，下方兩個輪子](/figures/kernel-engine-distro-car.svg)

早期有名的發行版有 Slackware、Debian，還有 Red Hat。Red Hat 是 Marc Ewing 在 1993 年弄出來的，他很早就用 Linux，用了一陣子發現自己花在管機器上的時間比寫軟體還多，於是在杜克大學附近公寓的客房裡做了一個發行版，名字來自他大學時戴的一頂紅白條紋長曲棍球帽。他替 Linux 補上讓它像個專業產品的周邊，像是 Red Hat 套件管理工具，讓使用者加、移除、更新軟體套件。1995 年他和同事 Robert Young 開了公司，賣光碟，也賣訓練、教育和客戶支援。

怎麼靠免費的東西賺錢？Young 愛用番茄醬做比喻：有番茄、糖和醋的人都能做番茄醬，Heinz 卻拿著八成市場。也有人把這門生意比成賣瓶裝水，包裝不同，水是同一種水。

## 1998 年夏天：Intel 發現客戶在用 Linux

採用曲線一開始很小，長得快。1992 年初 Linux 大概幾百個使用者，1996 年一兩百萬，到 1997 年中，全球用戶保守估計 300 到 500 萬。對比 Windows 的 1 億和麥金塔的 5,000 萬以上還差得遠，可是斜率在那裡。

![一張用戶數圖上 Windows 與麥金塔是兩條很高的水平線，Linux 貼在底部幾乎看不出來，右上角放大框裡同一條線陡直上升](/figures/linux-slope-not-height.svg)

價格是一個因素，但不只是價格。一位使用者說 Linux 近乎「crash-proof」，這直接換成生產力。進階使用者愛的是看得到原始碼：有人把 Linux 改到 Palm Pilot 上跑，洛斯阿拉莫斯的研究人員把 68 台 PC 串起來模擬原子震波。《Byte》1997 年寫過柯達的一位系統顧問在 Photo CD 專案裡裝 Linux，替公司省下 1 萬美元的高價 UNIX 支出。

缺點也明顯。應用程式比 Windows 和 Mac 少很多，沒有好用的 Office 或 Visual Basic。出事了要查什麼文件、打電話給誰——這正是 Red Hat 和 Caldera 站的位置。還有名聲：Linux 和 UNIX 沒有直接血緣，卻常被連在一起，於是也繼承了 UNIX 難懂難用的氣味。主管會問「這東西你也敢放關鍵伺服器？」，而問的時候，它可能已經在他公司某個角落跑著了。1998 年一位匿名系統管理員對《舊金山紀事報》說：

> 「很多管理層不信任 Linux，因為它免費。可是他們讓我負責跑他們的伺服器，我就會用最好用的那個。最好用的是 Linux。」

1998 年初，Intel 開始收到全國各地的奇怪請求，費米國家實驗室這類地方的工程師和研究員要 Intel 把數學函式庫移植到 Linux。在那之前 Intel 碰 Linux 的程度大概是修一兩個臭蟲。它去問那些替小型網路服務供應商做白牌伺服器的代工廠，發現 Linux 的成長在往上炸：近兩成的公開網站伺服器在跑它——以一個桌面幾乎沒有身影的作業系統來說，這個市占高得意外。消息直上安迪・葛洛夫，他用了頗有顏色的語言表示他們該做點什麼。

Intel 高層去見 Red Hat，開了幾場會，越聽越困惑：Red Hat 不擁有核心軟體產品背後的智慧財產，那東西誰都能免費拿，這怎麼賺錢、怎麼投資？Red Hat 那邊繼續講番茄醬，Intel 內部的 Linux 擁護者則補上網路服務供應商的採用數據。最後管理層被說服了，兩家開始談合作。

這背後還有一層。Intel 正在做代號 Merced 的新晶片，那是它 64 位元 IA-64 伺服器架構的第一個實作，後來叫 Itanium，號稱快得驚人。可是他們怕 NT 又把這顆晶片的本事綁住——32 位元那次就綁了整整十年。微軟下一版 NT（當時叫 NT 5.0）從 1998 延到 1999，再延之後改名 Windows 2000，剛好加深了這個擔心。支持並貢獻 Linux 的開發、把它調到吃得下 Intel 最新的矽，就能養出一個 Windows 的替代品。

接著 1998 年夏天，大公司一個接一個宣布。6 月，業界最保守的 IBM 之一說要把開源網站伺服器軟體 Apache 放進它的電子商務工具組——Apache 不是 Linux，但多數 Apache 跑在 Linux 上。IBM 1996 年替亞特蘭大奧運網站選過它，現在正式蓋章，開源拿到進企業的第一個立足點。

7 月 6 日，InfoWorld 登了一篇〈Linux 還沒到臨界量〉，文中 Oracle 和 Sybase、Informix 都說沒有要出 Linux 版資料庫，理由是沒看到客戶需求。三天後，Oracle 宣布要把 Oracle8 移植到 Linux。這個急轉彎的一大原因是 7 月在 Santa Clara 辦的「Linux 的未來」座談，900 多人去看 Torvalds 和其他人討論開源到底是不是一陣風、該怎麼推動應用廠商移植。到 9 月，Computer Associates、Corel、Informix 都有了 Linux 版本。

Intel 也在那場座談上。它的 Sunil Saxena 上台說 Linux 正在變成網路服務供應商首選的作業系統，同時點出它的弱點：擴展性、高階硬體的驅動程式、大記憶體支援。9 月 29 日，話變成了動作——Intel 連同網景和 Benchmark、Greylock 兩家創投投資 Red Hat，承諾技術貢獻和一位專職的工程聯絡人，還加入了 Linux International。另一張骨牌被低估：Benchmark 有位合夥人同時是 Dell 的董事，透過他，Red Hat 坐到了 Michael Dell 面前。Dell 後來投了 Red Hat，更重要的是 1999 年初宣布在工作站和伺服器上預裝 Linux，第一家這麼做的大廠。

消息出來，媒體狂猜 Intel 和微軟的關係要出事。Red Hat 高層在《Under the Radar》書裡回憶，微軟「went ballistic」，那個週末 Intel 高層接了好幾通來自微軟對口的怒電。1998 年 5 月以前，微軟或許還能把這筆投資擋掉，可是那個月美國政府以獨佔行為起訴了它，審判和外界盯視讓它得收手。對外，微軟拿 Red Hat 當證據，說自己並沒有獨佔作業系統市場；後來還用 Linux 的存在來主張市場競爭夠激烈、政府不該拆分它。

對內是另一回事。1998 年 10 月，一組被稱為萬聖節備忘錄的文件外洩，裡面把 Linux 這類自由軟體稱為 Windows 的長期可信威脅。微軟據報成立了「Linux 攻擊小組」，架了一個「Linux Myths」網頁，聲稱要「從炒作退一步看現實」，逐條反駁「Linux 效能勝過 NT 4」「Linux 比 NT 4 可靠」「Linux 免費」這些說法。1999 年 4 月，它贊助第三方實驗室 Mindcraft 做測試，結果是 NT 當檔案伺服器快 2.5 倍、當網站伺服器快 3.7 倍。

Intel 躲開蓋茲怒火的辦法是宣布自己作業系統中立：Linux、NetWare、Solaris、Windows 2000，它要全部都在自家硬體上跑得好。2010 年 Intel 把這套瑞士策略正式命名為 Port of Choice，不過 Pat Gelsinger 2001 年就說這是長期策略了。作業系統廠商只能接受，因為當時 Intel 的矽沒有真的替代品。

## 2001 到 2004：從四顆 CPU 到六十四顆

硬體先往上推。1998 年中 Pentium II Xeon 帶著更高時脈和 512KB 的 L2 快取進中階工作站與伺服器；1999 年 3 月 Pentium III Xeon 便宜又快，靠一個叫 Profusion 的東西支援 8 路系統，把先前 4 路的天花板捅破——這在當時的資料中心正造成效能問題。要注意 4 路和 8 路得作業系統配合，NT 和 Windows 2000 做得到，Linux 當時有問題。

![縱軸是單一系統能用的處理器顆數，UNIX 一開始就有一條最高的水平線，Linux 從最低的一階逐年往上墊成階梯，最後一階追到同一高度](/figures/cpu-ceiling-staircase.svg)

真正把市場翻過來的是工作型態。服務網站、代管郵件、防火牆這些事和跑資料庫或分析軟體不一樣，公司算了算，用一堆 Intel 矽跑 Linux 的節點橫向鋪開，比直向買一台巨大的 UNIX 伺服器划算。Sun 起初歡迎 Linux，這符合它「開放」的口號，於是把 Java 開發工具組移植過去，也出了工作站硬體的 Linux 版，給人的印象是機器跑 Linux 還是 Solaris 都好、只要是 SPARC 機器就好。問題在於它不必是 SPARC 機器。

網路股泡沫破掉之後這個趨勢加速。創投的錢乾了、新創開始倒，省錢成為主旋律，公司要嘛買清算來的二手設備，要嘛轉 Linux。Amazon 2001 年做了一次大規模的 Linux 轉換，季度申報文件裡說估計每季省下 1,700 萬美元；被問到怎麼做的，發言人說：

> 「後端技術我們一向少講，一部分是因為學費很貴，我們不想讓別人用我們的學費上學。」

網路券商 Etrade 2006 年的案例研究更直白：一台 25 萬美元的 Sun 4500 Enterprise Server 能服務 300 到 400 個使用者，一台 4,000 美元的 Linux-Intel 機器只服務 180 個。缺口怎麼補？買兩台。

![左邊一個巨大方塊代表二十五萬美元的單機，右邊兩個極小方塊代表各四千美元的機器，兩邊服務的人數幾乎一樣](/figures/scale-up-versus-scale-out.svg)

從 2001 年起，Intel 加 Linux 的機器好到足以一步步換掉 Sun 的位置，從機票票價算到大宗商品合約交易到金融計算。Sun 自己也試了橫向擴展的網站機種 Netra，2001 年的 X1 低到 1,000 美元，可是商品化 x86 的每元效能還是更好。從 SPARC 上的 Solaris 轉到 Intel 上的 Linux 這一波，Sun 始終沒做出像樣的回應。

低階打完，Linux 開始往上爬。2000 年底，IBM 執行長 Lou Gerstner 相信 Linux 會像網際網路一樣改變世界，宣布投入 10 億美元、調 1,500 名員工。2001 年 1 月 Linux 2.4 發布，Red Hat 很快跟上。它晚了一年，但處理掉 spin lock 這類問題，讓 Linux 能在單一系統裡用上 16 顆、甚至 32 顆處理器——1999 年 Mindcraft 測試裡最痛的一槍，就是 Linux 2.2 超過兩顆 CPU 就擴不上去，而 NT 4.0 和 2000 有 4 路、8 路甚至 32 路支援。

2.4 沒有讓 Linux 一夜之間挑戰得了高階 UNIX 機器，可是能穩穩吃下 4 到 8 顆 CPU，就替 Intel 上的 Linux 清出了一條往中階運算任務衝的路。經濟帳變得好看：一台裝四顆 Xeon、跑 Red Hat 的 Dell 伺服器 2.4 萬美元，是對等 Sun Fire UNIX 機器的一半價錢，效能一樣。Red Hat 和 IBM 直接對著 Solaris 的客戶群打；惠普和 SGI 則開始讓自家跑專有硬體的客戶選擇轉去 Linux 方案，理由是保住客戶關係比較重要。2002 年伺服器市場整體難過，Linux 機器還是長得漂亮：Gartner 說那年 Linux 伺服器硬體營收成長 63%，UNIX 硬體營收掉 11%。

![兩個面積相差懸殊的方塊，大的方塊上方一支向下的箭頭，小的方塊上方一支向上的箭頭](/figures/unix-shrinking-linux-growing-2002.svg)

規模上 UNIX 還是大得多，2002 年 170 億美元對 Linux 的 20 億美元，因為那些是賣得貴的高階機器；壓力已經在了。到 2004 年，Sun 伺服器的平均售價從 22,920 美元掉到 15,860 美元，少了 31%。

最後一道牆是 64 位元。Intel 1999 年 4 月開了 Project Trillian，讓一群公司祕密拿到 Itanium 原型去做 Linux 移植，2000 年 2 月把 IA-64 的 Linux 原始碼早期釋出給社群，這在開源發展史上是個里程碑。只是 Itanium 沒取代 32 位元的 x86（惠普用它換掉自家專有 UNIX 的處理器）。開啟 64 位元轉換的是 AMD：2003 年中的 Opteron 系列，而 Intel 2004 年的 Nocona Xeon 採用了 AMD 那套向下相容的 64 位元擴充。

這件事的份量在記憶體。32 位元的 x86 電腦大約只能定址 4GB 記憶體，遠少於資料庫或科學模擬這類高階應用要放進記憶體的量；走到 64 位元之後，x86 系統可以定址幾十甚至幾百 GB。有人當時覺得 Intel 採用 64 位元的方式像個權宜之計、只是通往 Itanium 的過渡，結果不容爭辯：x86-64 把 UNIX 最後的圍牆敲掉了。

![左格一道低矮天花板把 x86 的方塊壓在底下，UNIX 的高塔站在天花板之上；右格天花板被打斷，x86 的方塊一路疊到同樣的高度](/figures/four-gigabyte-wall-removed.svg)

## 2005 年以後：Linux 吃掉 UNIX，微軟靠身分留住人

2003 年底的 Linux 2.6 後來成了一個標誌性的核心版本：速度、網路、支援到 64 顆處理器，全面改善，可以算第一個企業級的 Linux 核心。它到的時機也剛好，那時用著老掉的 NT 4.0 的使用者正要進升級週期，IBM、惠普、Dell 這群海妖對著他們唱歌。IBM 衝得最前面，訓練上千人、幫開發者把應用改寫到 Linux、砸行銷預算和打折機器給潛在轉換者。

面對一個誰都能免費下載的東西，微軟的說法是：大家已經在用 Office，換到 Linux 比直接買 Windows Server 授權還貴又麻煩。2004 年它跑了一個「Get the facts」行銷活動，拿研究報告說明 Windows 比 Linux 好，那些研究被指不夠中立、可能誤導。

我聽完覺得有效得多的是另一招：Active Directory 帶來的深度鎖定。Ben Thompson 後來稱它是「史上最有價值的免費產品之一」。它隨 Windows 2000 推出，負責驗證和授權一個 Windows 網路裡所有使用者與資產：推更新、照組織圖把安全權限指給群組、驗證身分。有了它，管理者可以把一位新主管入職一次設好、給他該有的工具權限，使用者則用一組憑證登入各種東西，一堆散的 Windows 機器就變成一個管得動的組織。

Ben 的重點是，這也讓微軟握住了個人身分。身分這東西長到組織的深處去，所以轉換成本被推到遠高於「換一套作業系統」的層級。於是在一群人預言 Linux 會把微軟打下來的時候，Windows Server 的銷售一路成長，2005 年 Windows 的營收首次追平 UNIX，隔年超過。Linux 也在長，可是它的成長來自吃 UNIX，以及在 Windows 從沒站上的新市場長出來：超級電腦、高效能運算、網站，再到 2010 年代的雲端。

UNIX 伺服器的銷售之後慢慢下滑，沒有死絕，今天還有客戶在 Solaris、HP-UX 或 AIX 上。那些落在後面的應用多半集中在銀行和醫療，出於各種理由，移到 Linux 太難或太冒險。

那麼 UNIX 為什麼輸？講者自己的提法是：UNIX 輸在商業模式。這些垂直整合的王國在 Intel 帶著量產經濟學進來之前，運作得好得很。先是 Windows NT 重擊了它們，然後 Linux 打得更兇——把 UNIX 有的東西都給客戶，不附帶鎖定。等 Linux 好到一個程度，UNIX 廠商只剩一條路：自己改賣 Linux。

## 「我看好的技術更強，為什麼漲的是對手」

這集最會讓人心裡癢的是 Pentium Pro 那一段。它在某些整數測試上贏了當時最快的 RISC 晶片，而 MIPS R10000 隔不久就追了回來。規格上的領先只維持幾個月，可是市場的結構被改掉了，因為改掉它的是量，不是那幾個分數。

我自己看一家公司的位置時會先分清楚：它的優勢是「規格領先」還是「成本曲線領先」。規格領先每一代都得重新贏一次，對手補完就沒了；成本曲線領先會自我強化——量帶良率、良率帶成本、成本帶現金、現金再投回製造。Intel 那十年靠的是後者。

![左格一條鋸齒線反覆衝高又掉回原位，右格一條複利曲線一路往上不回頭](/figures/spec-lead-versus-cost-curve.svg)

這個判讀也有失效條件，而這集把它講得很清楚：當瓶頸不在成本，而在某個物理上限，便宜的那一邊根本進不去。32 位元 x86 只能定址 4GB 記憶體，所以高階資料庫和科學模擬的那塊地，UNIX 守了四、五年都沒事。對答案的方式因此是盯那個上限什麼時候被拆掉——是 2003 年的 Opteron，不是每一代的效能評測。

## 「這家公司的護城河看起來很深，我該信多少」

UNIX 的鎖定是真的。買一整套進去，軟體綁硬體、硬體綁廠商，換不掉。它最後被繞過了，沒被攻破：客戶要服務網站、代管郵件、擺防火牆的時候，那些工作本來就不在 UNIX 機器上跑，於是直接買了另一種機器。UNIX 廠商的資料庫主機守了很久，可是客戶要架新網站時沒人想到他們。

所以看護城河，我會先問它鎖住的是「客戶現在這批工作」還是「客戶以後會長出來的工作」。前者會隨著工作型態搬家而慢慢失血，而且外面看起來一切正常，因為既有合約還在續。

Active Directory 是另一種。它鎖的是人的身分，身分會跟著組織長大，新增一個人、新接一個系統都得回來這裡認證，所以它鎖住的是「以後的工作」。我拿這組問題看自己持股時，問法是：這家公司收的租，收在客戶已經裝好的東西上，還是收在客戶每多一個人、每多一個專案都要再經過的那一層。前者會流失，後者會隨客戶變大而變多。

![左格一圈圍牆把一塊現有工作圍住，新的工作方塊長在牆外面不經過它；右格一條底層橫條，上面每一個新方塊都有線往下接進這條底層](/figures/moat-on-now-versus-later.svg)

## 帶得走的一件事

一個便宜又到處都有的東西，會先去搶「還沒長出來的那些工作」，在那裡把自己練熟，再回頭要本來的地盤。UNIX 被換掉的過程裡，沒有一場正面對決。

我試過的一個做法：找一件你「換起來太麻煩所以一直用」的東西——一套軟體、一家銀行、一份工作流程都算——寫下如果今天要換掉，第一週會卡在哪一步，那一步是誰在替你做。我自己寫完發現卡住的地方跟功能無關，是我的帳號、歷史紀錄、和別人找得到我的方式都綁在那裡。那一層就是它真正在收租的地方。
