## 上一篇留下的問題

九月六日我寫過[怎麼用一行額度表排 AI 的班](/blog/codexbar-quota-dispatch/)：四家訂閱、四種額度窗，一支腳本每十分鐘問 CodexBar 四家剩多少，換成綠黃紅三色印在每則訊息前面，派工照那行派。

那篇沒講的是：額度用完之後呢？我這台機器上有三十幾支排程在跑，主力是 Claude。Claude 的五小時窗一撞牆，排程不會停，只會靜靜地做出壞東西。這篇講我怎麼處理這件事，用了三個零件，加上排程本身的一次減肥。

先講清楚三個零件各是什麼，再講它們怎麼接起來，最後放我付過學費才知道的事。

![三層橫條由上到下堆疊，上兩層被一條實線串成「翻牌鏈」，最下層 herdr 在鏈外用虛線標示不參與翻牌](/figures/three-parts-three-layers.svg)

## 三個零件，三層

CodexBar 是讀數的。一個開源的系統匣小工具，附一支命令列，能把四家 AI 登入後的用量吐成結構化資料。它只負責告訴你「還剩多少、幾小時後重置」。

監國協議是決定誰當家的。名字取自君主不能視事時的代理攝政：主力 agent 額度撞牆，裁判自動把主導權交給次要的 agent 看守；看守只能在隔離區做事，公司的治理檔案在作業系統層上鎖；額度回來，一個指令交還，機器列出看守期間改了哪些檔給我逐條收。這一層是我自己寫的，倉庫在文末。

herdr 是 agent 住的地方。上一篇[操作手冊](/blog/herdr-complete-guide/)講過，它管的是每個 agent 現在是在做事、卡住、還是做完。這裡要老實說一句：herdr 不參與翻牌。監國跑在排程與命令列上，herdr 是同一台機器上的另一層，它給我的是「哪個 agent 卡住了」這個訊號，而卡住跟額度用完在畫面上長得一樣，所以兩層要一起看。

## 合起來的一天

每則訊息前面先印一行。這是我每天看最多次的東西，九月十日的實況長這樣：

```
【額度（7分前）】Claude週 🟢剩74%·123h後重置(Fable剩67%)｜Codex週 🟡剩32%·132h後重置🔥超前｜Grok月 🔴剩0%·16h後重置｜agy 🔴實測失敗 ⇒ 機械→codex、工程→codex、判斷→fable、X爬文→grok(⚠️紅)、寫程式→codex
```

每格三欄：燈號、幾小時後重置、有沒有超前。超前的意思是用量比時間進度快了十五個百分點以上，會撐不到重置。同燈號的兩家比的是餘裕，不是裸的剩幾成。

![一張以窗口已過為橫軸、額度已用為縱軸的圖，一條同步斜線把區域分成上下，一家落在線上、另一家高懸線上方標為超前](/figures/room-to-spare-versus-percent-left.svg)

這一行只建議，不翻牌。

翻牌的是裁判。一支腳本每五分鐘跑一次，只認硬證據：CodexBar 讀到「五小時窗用滿」就寫一筆證據，附重置時間。裁判是狀態檔唯一的寫者，任何人不得直接改那個檔。九月九日早上的一筆證據長這樣：

```
{"ts": "2026-09-09T09:08:02+08:00", "engine": "claude", "signature": "[codexbar] claude 5h window 100% used. resets at 2026-09-09T10:40+08:00"}
```

翻牌那一刻機器自動做三件事。開一個隔離區資料夾當看守的工作區，拍一份快照，把七個禁區設成唯讀：決策帳本、公司憲章、設定檔、規則、技能、記憶、交接檔。看守在這些地方寫入會直接被作業系統拒絕，那是設計不是故障。

![一個大框代表整台機器，左邊一小塊亮框是看守唯一可寫的隔離區，右邊七個上鎖的灰格是禁區](/figures/caretaker-writable-corner.svg)

同時產一份接棒包給接手的 agent：隔離區路徑、守則全文、這一刻的額度行、交接檔、排隊事項。

看守期間接手的 agent 能做的事有邊界。能接著做交接檔裡的「回來先做」、改腳本、把產物寫進隔離區、把需要我決定的事排進佇列。不能發決策編號、不能寫記憶、不能改技能、不能對外發布、不能動排程。每做一件事在帳本記一列。卡住兩次就停，換下一件，不暴力重試。

額度回來，我打一個指令。它先花一次最小呼叫探測主力 agent 活了沒，活了才翻回來、解鎖禁區、比對快照、印一份交還報告。九月九日那場的報告是這樣：看守從九點零八分到十點四十三分，鎖了 3,521 個檔，看守期間改了 4 個檔、新增 0、刪除 0，四個都是排程的狀態檔。我看完清單，逐條收。

九月六日這套上線之後，看守期一場接一場，到九月九日已經十一場。在那之前，兩個月裡自動翻牌一次都沒發生過。為什麼，放在後面講。

## 排程跟著調

翻牌解決「誰當家」，解決不了「為什麼這麼快撞牆」。九月九日我做了一次提示詞審計，掃到三十五支走 Claude 命令列的排程，零支帶減肥旗標。每次呼叫預設載入公司憲章、規則、記憶、輸出風格、所有掛鉤，合計約十四萬字元的治理檔。其中至少六支只是要模型寫一兩句話。

同一句題目實測，一次呼叫的字量：

| 旗標 | 字量 | 相對正常 |
|---|---|---|
| 正常（載入全部治理檔） | 105,758 | 基準 |
| 只讀本機設定 | 35,052 | 少 67% |
| 安全模式 | 16,585 | 少 84% |

剩下的一萬六千是命令列工具自己的系統提示與工具定義，關不掉。

![三根長度遞減的橫條顯示每次呼叫的字量，最短那根後面有一條虛線標出關不掉的地板](/figures/context-per-call-floor.svg)

判準一句話：機械型的單句呼叫加安全模式並把推理強度調到最低；判斷型的排程，像持股巡視、週情境、四源籌碼，只調推理強度到中等，不加安全模式，因為它們要技能、要工具、要公司脈絡。判斷活不降級，這條在派工層跟排程層是同一條。

最後改了二十一支，跳過十四支。跳過的裡面有一支是量尺本身，改了等於改被量的東西；有一支明文禁止走這條路；有一支走的是 Grok。

一個反直覺的結果：我先改了公司憲章本身，搬走十二處改版歷史，實測只減 7.5% 的字量，對每次呼叫的總字量沒有可見影響。省額度要靠排程旗標，改治理檔的價值在行為面，不在字數。

## 五件我當初沒想到的事

第一，翻牌管得到誰當家，管不到正在跑的排程。九月七日兩次撞五小時窗，剛好撞上發文線的英文配圖步驟：翻譯呼叫回空字串，每張圖被判「缺翻譯，跳過」，文章照發、Substack 照寄，兩篇英文版零張圖上線，沒有任何警報，是我自己看到才知道。翻牌之後要多做一件事：列出那段時間跑過的、步驟裡有呼叫主力 agent 的排程，逐一驗產物，不驗紀錄。

![左邊一欄紀錄全是打勾，右邊應有六張圖的位置全是空的虛線框，兩欄並列對照](/figures/green-log-empty-output.svg)

第二，只有備援沒有閘，等於沒有備援。第二次撞牆時備援已經接上 Codex，卻撞到 Windows 裸打 codex 找不到 .cmd 的洞，一樣回空。後來的規矩是跨家備援加產物數量閘：做完數一數，少了就通知。

第三，裁判的眼睛長在調度層上。第一版的裁判靠一支包裝腳本回報撞牆，但三十幾支排程裡只有三支走那支包裝，其餘直接呼叫命令列。裁判兩個月沒看到任何證據，自動翻牌從沒發生過，全靠我手動。

![左右兩格各有三十五個排程方塊，左邊只有三個被眼睛的視線照亮，右邊三十五個全部照亮](/figures/referee-eye-coverage.svg)

第二版改讀 CodexBar，是繞過這個洞，不是補上它。

第四，兩顆腦寫同一本帳，撞號是必然。八月十一日看守與我同時作業，決策編號撞了三次：我送出的號碼看守已經用掉、同號共存連重複檢查都沒攔到、修的時候又撞一次。每次都拿「我讀到的當下」當「寫入的當下」。修法是登記後讀回驗證，根治要把號碼分配放進同一次帶鎖的交易，這件事還沒做。

第五，靠環境變數關掉的保險，只在記得帶的人手上。九月七日早上六點半，一支排程跑測試，測試在暫存狀態檔上模擬翻牌，第二版的掛鉤沒看狀態檔是不是正式的那份，對真系統開了一場看守期，鎖了 3,411 個檔包括我的記憶目錄，到十點零六分我寫檔被拒才發現。能從資料本身判斷「這是不是正式的」才是真保險。

還有一條是九月九日才拍板的：備援層數不等於備援有效。三家同計費週期的外部引擎會同一天倒光，等於一層；第四層要挑不同計費池。

## 倉庫在這裡

監國協議的技能與參考實作公開在 https://github.com/bockybocky/jianguo-skill ，MIT 授權。十個檔：一份英文說明、技能本體、看守守則、裁判、隔離區、證據轉接器、調度包裝、人用的命令列、兩份測試。

要搬到自己的環境有三步，這三步是我整理的，說明檔裡沒有專門的安裝段：把技能檔放進 Claude Code 的技能目錄；把腳本放進自己的腳本目錄，逐支改檔頭常數區的路徑、通知管道與探測指令；把裁判掛成每五分鐘的排程，跑兩份測試確認。說明檔開頭有一張流程圖與五條設計要點，不需要先懂我的術語。守則與技能本體是繁體中文，非中文讀者只能看說明與程式碼。

問題留言就好，這篇下面或方格子都看得到。

## 帶得走的一件事

我做完這一輪想到的一件事是：備援有沒有效，不看有幾層，看額度歸零那天有沒有東西在數產物。

我自己試過的做法是這樣。下次你的主力 AI 撞額度之後，先不要急著換家，開一張紙，列出那段時間跑過的自動化，每一條打開它的產物數一數：該有六張圖的有幾張、該有三段的有幾段。把少掉的那幾條寫下來。一週內至少會找到一條是靜靜地少了東西而沒人通知你的，那一條才是要先修的。
