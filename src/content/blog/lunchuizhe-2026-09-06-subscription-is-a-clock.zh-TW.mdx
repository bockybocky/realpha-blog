## 這集在講什麼

掄錘者（YouTube 頻道「抡锤者」）這集（2026-09-06 上架，14 分 45 秒）是前一集的續篇。前一集他用 API 接 GPT6，一個小請求燒掉九美元，留言區炸了：你不是有訂閱嗎，為什麼不用訂閱，用 API 當然貴。

他先澄清自己的訂閱是二十美元一個月的 Plus，額度不多，主要拿來替幾個頻道畫封面圖和講解用的插圖。然後他照留言的建議，把同一件事用訂閱制再跑一次，順便把留言區點名的 5.6 Luna 和 5.6 Terra 一起試了。

## 摘要重點

留言說 5.6 Luna 開高思考就變聰明。他給的任務是幫他把官方 GPT6 的接口加進自己的設定檔。額度只用掉 1%，便宜，但每一次回報都是假的，設定沒改對，最後一次直接把設定檔弄壞，Codex 打不開。他轉頭用 DeepSeek 修好，順手連他以前設定裡的舊錯誤也修掉了。他的評價很直白：這種任務都做不了，還會裝作做好了騙他，他不會為了把每個月二十美元用完而忍受這個。

5.6 Terra 他前一集講過：改一個設定腳本，五小時額度掉 6%，工作做不到三分之一額度就沒了。

重頭戲是 GPT6 走訂閱。他接回前一天做到一半的論壇程式，給它自己能找到的最小 bug：引用的格式排漂亮一點，游標停到下一行。結果三件事。第一，速度慢，三分鐘沒做完，比他本機最慢的 Qwen 27B 還慢，那台本機模型他曾經一次丟六個更難的任務，二十分鐘做完。第二，做對了，準確度高，他認為跟 DeepSeek V4 Pro 是同一個檔次。第三，這一個小改動吃掉五小時額度 15% 到 20%，一週額度的 4%。

![三條長度差很多的橫條，比較三個模型吃掉的額度；最短的兩條旁邊標著失敗，最長的那條才標著做對了](/figures/three-models-quota-vs-result.svg)

他順帶講了兩件小事。一是有人拿「一句話生一個小遊戲」的示範來證明頂級模型多強，他說那種難度低，便宜模型也做得出來，只是效果差一點；他手上這個論壇程式的難度比小遊戲高得多，這才是他量的地方。二是圖片生成的價格差：他這次的額度消耗裡，很可能有一部分是圖片模式本身就貴；DeepSeek 的圖片模式在他口中是白菜價，可以當玩具隨便玩。

他的結論分兩句。第一句是認錯：走訂閱比走 API 划算得多，沒有前一天想像的那麼貴。第二句是收回：他現在不敢像用便宜模型那樣一次丟六個任務，一丟額度就沒了，封面圖就不用畫了。所以他日常還是 DeepSeek V4 Flash 加本機 Qwen 27B。Flash 比 V4 Pro 差一級，Qwen 27B 介面做得漂亮但指令執行不夠準、表格解析會出錯。GPT6 是頭部模型沒有疑問，但沒有強到天上去，對一般工程師的日常任務來說，差距沒有跑分看起來那麼大。

## 延伸想法

看完這集，我心裡的問題是：同一個任務，API 九美元，訂閱 4% 額度，這兩個數字到底是不是同一件事。

![左邊一條連續往下、走出畫面的斜線；右邊一段一段往下掉的階梯，最後停在一條橫著的粗線上](/figures/money-slope-vs-quota-stairs.svg)

我拿自家的帳來對。我平常的工作九成以上跑在訂閱制上，四家工具各一份訂閱，按量計費的 API 只留給幾支小程式。這些工具會記錄每一次請求讀了多少、寫了多少，我把 2026 年 8 月 30 日到 9 月 5 日這七天的紀錄，照各家公開的按量牌價換算了一次（牌價 as-of 2026-06，快取讀取用折扣價、輸出用全價，屬估算）：

- 七天合計約 2,800 到 3,600 美元（區間來自其中一款模型的快取單價有兩種讀法），平均一天四到五百美元
- 最重的一天 9 月 4 日約 702 美元，其中 525 美元是模型重讀上下文的錢
- 9 月 5 日約 390 美元，重讀佔 287 美元

我沒有付這三千美元。

![兩根高矮不同的柱子代表兩天的帳，每根柱子底下約四分之三被塗成同一個顏色，那塊是重讀上下文的錢](/figures/one-day-bill-mostly-rereading.svg)

訂閱費把它攤掉了。但攤掉的東西沒有消失，它變成了另一種形狀：每五小時、每一週、每個月各有一個額度窗，用到底就得等它重置。我看今天傍晚的四家額度（as-of 2026-09-06）：一家週額度剩 76%，另一家週額度剩 25%，第三家月額度剩 25%，第四家五小時額度剩 11%，而且用得比時間快。

![四條長度不同的軌道由短到長排列，代表五小時、週、月三種窗，每條左邊填著剩下的額度，最短那條幾乎沒剩](/figures/four-quota-windows.svg)

這就是掄錘者說「不敢一次丟六個任務」的意思。他不是付不起，他付得起的是一個會走的時鐘，六個任務丟下去，時鐘直接走到底，接下來幾個小時他什麼都不能做，包括畫封面。

![上面一條額度條被六格塞滿一路頂到右邊的牆，下面同一條只填了一格，右邊還空著一大段](/figures/six-tasks-hit-the-wall.svg)

用 API 的時候，錢是連續的，多花就多付；用訂閱的時候，額度是一格一格的，用完就是牆。

所以我把兩個數字的關係寫成一句：訂閱制不是把錢省下來，是把錢換成時鐘。九美元和 4%，講的是同一個任務在兩種計價方式下的樣子，差別在於一個花的是錢，一個花的是這段時間裡你還能做幾件事。

## 那我該訂閱還是按量

你會問的是這個。我的答案跟掄錘者一樣是訂閱，但理由不是划算，是可控。按量計費最可怕的地方是那個九美元的請求發生之前你不知道它會是九美元。訂閱制把最壞情況封住了：再怎麼燒，燒到的是額度，不是餘額變負。

按量付費划算這個信念從哪來？它來自雲端運算的年代。2006 年前後雲端主機開始用「用多少付多少」收費，那時候它是對的，因為一般人的用量小又不穩定，包月等於替沒用到的部分付錢。今天的處境不一樣：接進代理人工具之後，一個請求會自己去讀整個專案，用量不再是你手動敲幾次的量，是工具替你決定的量。用量一旦不受你控制，包月反而是安全的那一邊。

這裡有一個常見的誤會值得拆開：很多人拿「一個月二十美元」跟「一次九美元」比，得出訂閱划算十倍的結論。這個比法少了一個變數。九美元買到的是一個沒有上限的請求，二十美元買到的是一個有上限的月份。掄錘者那個小任務吃掉週額度 4%，換算成一個月，同樣的任務他只能做一百次上下。一百次夠不夠，看的是他的工作長什麼樣，不是看價目表。

可控之後，剩下的問題就從「錢夠不夠」變成「時鐘怎麼排」。我自己做了一件小事：讓工具在我每丟一句話之前，先印一行四家額度剩幾成，然後照剩得多的那家派工。讀大檔、轉格式這種機械活派給最便宜、額度最寬的；要判斷的事留給最貴的，而且盡量不要讓它讀原料，只讓它看結論。這一週最先見底的是我拿來跑程式改動的那家，週額度只剩 25%，原因跟掄錘者一樣：改程式這件事讀得多。

掄錘者的解法是另一種形狀：把日常全交給便宜的雲端模型和本機模型，貴的只在需要的時候碰一下。他的本機 Qwen 27B 一次吃六個任務不用看時鐘，因為那個時鐘是他自己的電腦，電費而已。這兩種做法都在做同一件事：把會撞牆的任務移到不會撞牆的地方。

![左邊一個框裡有一根快見底的額度柱，三個任務擠在旁邊；一個箭頭把任務移到右邊沒有柱子的框，那裡六個任務攤得開](/figures/move-work-off-the-clock.svg)

再講一句我的體會。留言區叫他開高思考、換 Luna、換 Terra，那些建議都在談模型，他的實測在談時鐘。同一個模型，接 API 跟走訂閱是兩種東西；同一份訂閱，一次丟一個任務跟一次丟六個又是兩種東西。跑分表上沒有這幾條線，帳單和額度頁上有。

## 帶得走的一件事

我看完這集留下的一句話是：訂閱不是把錢省下來，是把錢換成一個會重置的時鐘。我自己是因為看見那家只剩 25% 的週額度，才明白掄錘者為什麼不敢丟六個任務。

我試過一個做法，你要的話可以試試：下次要丟一個大任務給 AI 之前，先打開它的額度頁，把剩幾成、幾點重置，寫在任務的第一行。做完回頭看那一行，把掉了幾個百分點寫在後面。三次之後你會有一張自己的價目表，上面寫的不是美元，是這種任務要吃掉你幾小時的時鐘。
